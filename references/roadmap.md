# Software Development Learning Roadmap

Use this as a coverage map for a learner's chosen direction. Adapt order, depth, examples, and pace. A learner can start building useful software before covering every topic here.

## 1. Programming foundations

- Values, types, variables, expressions, input and output
- Branches, loops, functions, parameters, return values, and scope
- Collections and common data structures
- Errors, exceptions, and reading error messages
- Decomposing a problem into steps; tracing a program
- Basic algorithms and choosing clear names

## 2. Daily development tools

- Editor or IDE, terminal, files, paths, and environment variables
- Running programs and managing dependencies
- Git fundamentals: repository, status, diff, commit, branch, merge, and remote
- Finding trustworthy documentation and asking precise technical questions
- Debugging with small reproductions, logs, breakpoints, and hypotheses

## 3. Software design and quality

- Breaking a program into modules with clear responsibilities
- Interfaces, cohesion, coupling, and choosing appropriate abstractions
- Automated tests: unit, integration, and end-to-end; when each helps
- Refactoring while preserving behavior
- Code review, readable diffs, documentation, and technical tradeoffs
- Complexity and data structures at a depth suited to the learner's goals

## 4. Choose a development direction

Choose one primary path first; add other paths only when they support the learner's goals.

- **Web:** HTML, CSS, JavaScript or TypeScript, browser and HTTP basics, a frontend framework when useful, server-side APIs, forms, accessibility, and deployment
- **Backend:** a language and web framework, API design, validation, authentication and authorization, relational databases and SQL, migrations, caching, and service operations
- **Mobile:** a platform or cross-platform toolkit, UI state, navigation, local storage, network requests, accessibility, and app release basics
- **Data or automation:** scripting, files and formats, APIs, data cleaning, repeatable jobs, and responsible handling of data
- **Systems or embedded:** memory and processes, operating-system interfaces, concurrency, networking, and hardware constraints as relevant

## 5. Data and connected systems

- Relational modeling, SQL queries, constraints, indexes, and transactions
- HTTP requests and responses, status codes, JSON, and API contracts
- Identity, authentication, authorization, and secrets management
- Data validation, error handling, rate limits, and external service failures

## 6. Delivery and operations

- Configuration for local, test, and production environments
- Build and release processes; continuous integration where appropriate
- Deployment, logs, monitoring, backups, and rollback concepts
- Reliability, performance, security, privacy, and cost tradeoffs
- Maintenance, upgrades, incident learning, and retiring software safely

## 7. Professional practice

- Clarifying user needs and defining acceptance criteria
- Estimation, task breakdown, and communicating uncertainty
- Working with branches, pull requests, and collaborative review
- Reading unfamiliar code and making incremental changes
- Ethical and legal considerations relevant to the product and data

## Learning checkpoints

Use observable outcomes rather than a fixed number of lessons. A learner is ready to move on when they can, with an appropriate amount of help:

- Explain the central idea in their own words.
- Apply it in a small task that is not identical to the example.
- Find and correct a plausible mistake using evidence.
- Describe one relevant tradeoff or limitation.

If they struggle, narrow the task, revisit a prerequisite, and try again with a different example. Do not make one difficulty a reason to restart the entire roadmap.
